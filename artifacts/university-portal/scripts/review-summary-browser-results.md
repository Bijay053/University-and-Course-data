# Review summary browser verification

Run `PORTAL_URL=http://localhost:80 node artifacts/university-portal/scripts/review-summary-browser.mjs` **after** the managed portal workflow is running and serving the latest frontend bundle. The script launches Chromium/Playwright against the actual `/scraping` page, routes every `/api/**` request to synthetic read-only responses, and rejects writes. No real account, course, or database is used.

Coverage: **every** initial staged count/list and historical detail request contains `?view=summary`; no evidence-detail request is made before opening Sources; Sources loads the complete synthetic snippet in the DOM and `title` attribute (the UI visually line-clamps it); a 503 response displays an explicit error and Retry recovers; switching history jobs while a detail request is in flight does not show the previous job's snippet. The primary editable Review row also opens its Edit form with a detail-only Sub Category value hydrated through the fenced course endpoint, without sending a write. The timing output records initial Review render and source expansion with a 40 ms mocked network delay in two scenarios: `full` **forces a full 100-row response even to the current `?view=summary` request**, simulating the old eager payload; `summary` returns 100 small rows. This is an actual browser render comparison of two routed payloads through the current frontend, **not** a measurement of a legacy frontend build.

The script reports UTF-8 bytes for JSON-serialized synthetic payloads of 100 rows, including large raw source and evidence fields in the full fixture. Those payload-byte counts are **fixture sizes**, not measured transferred HTTP bytes; the browser timing uses Playwright-intercepted, delayed responses, not an HTTP/backend/SQL benchmark. The benchmark cannot establish production server latency, compression ratios, or database savings. For those, measure real authorized GET requests in a separate non-writing environment with a populated database.

Latest run: `PORTAL_URL=http://localhost:80 node artifacts/university-portal/scripts/review-summary-browser.mjs` passed against the running portal (single cold browser context per scenario). Full fixture: **2,407,481 bytes** JSON; summary fixture: **46,289 bytes** JSON, a **98.1% reduction**. Initial Review render (navigation to 100 pending entries): simulated-full **2,764 ms**, summary **1,747 ms**. First Sources expansion through mocked detail fetch: simulated-full **393 ms**, summary **1,422 ms**. Source expansion is noisy and dominated by browser scheduling/rendering; it is **not** evidence of summary expansion being slower. Rerun with warmed bundles, multiple repetitions, and real HTTP/DB instrumentation for production conclusions.
