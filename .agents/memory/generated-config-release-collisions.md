---
name: Generated config release collisions
description: Safety contract for reconciling runtime-generated university YAML with newly tracked release files.
---

Only an unchanged generated university stub with verifiable integrity may be moved out of an incoming tracked-file collision. Compare it with the immutable target revision: if the target contains every generated leaf path, hold the original outside the runtime overlay directory and delete it only after release verification succeeds. If any generated-only path remains, preserve the stub as a runtime overlay below the tracked recipe, so incoming release values win conflicts while generated-only values survive. Every unknown or edited untracked file must continue to block the release. Reconciliation must be failure-atomic: validate the whole collision set first and preserve exact rollback bytes through checkout and verification. A post-checkout failure restores a deferred stub as an overlay because the tracked target now owns its original path. Cleanup must repeat integrity, tracked-file, path-coverage, and digest checks immediately before deletion, and must ignore symlinks and unknown files.

**Why:** Production legitimately creates ID-specific YAML stubs, but Git must never overwrite a manual runtime file during a guarded fast-forward. Weak comment-only classification cannot distinguish an untouched generated file from an operator-edited one.

**How to apply:** New generated files need a digest over their exact body. A bounded legacy recognizer may accept only the exact historical template. Record a rollback manifest before moving anything; finalize it only after release verification and prevalidate every deferred backup before deleting any. The release exit path must accept the checked-out target for retained overlays, restore deferred files as overlays, and keep consumers paused if restoration fails. Audit by YAML leaf-path coverage rather than value equality, and retain an overlay whenever even one generated-only path remains. After a release changes a tracked recipe that already has preserved operator edits, verify the live effective config—not only the deployed Git revision—because restoration can legitimately replace the target's new leaf. Merge the missing leaf into the preserved operator recipe without discarding unrelated runtime edits.
