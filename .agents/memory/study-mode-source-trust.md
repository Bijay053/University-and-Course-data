---
name: Study-mode source trust
description: Why generated delivery values need semantic write checks and separate legacy review.
---

A selected AI/CSS extraction is not proof that a value describes delivery.
Reject curriculum/marketing prose rather than guessing a mode from words inside
it; preserve legitimate detailed delivery and study-load labels.

**Why:** A generated selector extracted an accounting introduction paragraph,
which was selected as study-mode evidence and propagated through staging and
approval. Provenance and confidence did not validate the field's meaning.
The preventive change was explicitly separate from review of stored records.

**How to apply:** Keep semantic validation shared across write paths, with
eligibility decisions seeing the original delivery/load facts before invalid
display values are cleared. Keep rejected source text available for review,
not selected as proof. Do not make reads silently clean legacy records or
replace missing delivery with a guessed on-campus default. Validate generated
rule coverage, repair fill counts, and selected proof semantically, not by
non-emptiness. Let fallback extraction see rejected generated values as missing,
while retaining raw candidates for review and independently credible
delivery/load facts for eligibility. Failure to recover is unknown, not
inferred campus delivery. Rejected generated prose does not prove online-only
delivery merely because it contains “online”; such a flag can defeat valid
on-campus recovery. Preserve genuine online-only authority and study load.

Automatic repair must withhold all field updates when fresh credible delivery
or load facts fail eligibility, including updates to approved staging rows.
Report a blocked repair rather than saving an excluded mode beside an unchanged
approval or silently unpublishing operator-approved data.

**Why:** Consuming the real extraction response can activate writes that were
previously ineffective; semantic field validation alone does not prove course
eligibility.

**How to apply:** Reuse the staging online-only and part-time policies on fresh
facts before applying or counting any automatic repair updates.

Storage coercion is a final safeguard, not a complete review workflow.

**Why:** A bind-time rejection can save an unknown mode while losing its
explanation. Removing a rejected candidate from selected proof can also erase
the very source a reviewer needs to inspect.

**How to apply:** Sanitize before persistence to retain warnings and rejected,
unselected candidates. Save imported candidates atomically with their course.
An already-empty mode still needs rejected evidence retained; that evidence
alone is not successful field repair. Clear its warning only after a fresh,
valid mode is explicitly written, never on an unrelated targeted update.

Legacy review must preserve award identity across redirects. A former top-up
URL that now lands on a full-degree page does not verify the old top-up route.
Likewise, a verified Full-time study-load label does not establish On Campus
delivery.

**Why:** Official partner redirects can collapse distinct awards, while course
pages legitimately use “Study mode” for study load rather than delivery.

**How to apply:** Record the stored URL and actual final destination separately;
keep unsupported replacements unknown and retain audience-specific alternatives.
Do not use a content-fetch response's echoed request URL as redirect proof.
